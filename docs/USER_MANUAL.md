# 사용자 매뉴얼 — Local Log Analyzer

이 앱은 장비 로그를 PC 안에서만 분석한다. 사용자가 승인한 정상·비정상 사례를 쌓아 두고, 새 로그가 들어오면 그 사례와 비교해 다음을 보여 준다.

- 이상 여부
- 비슷한 과거 사례
- 원인 가설
- **해야 할 대응**

AI(로컬 Ollama)는 보조자다. 확정은 항상 사용자가 한다.

## 1. 화면 구성

- 상단 탭: **정상 로그 학습 / 비정상 로그 학습 / 신규 로그 분석**
- **관리** 메뉴
  - 학습 사례 관리, 분석 이력, 운전 모드 관리, 승인된 지식 보기, 설정, 백업 및 복원
- 상태 표시줄: 데이터 폴더, DB 상태, Ollama 연결 상태('다시 확인' 버튼)

## 2. 먼저 할 일: 운전 모드 등록

**관리 → 운전 모드 관리**에서 장비의 운전 모드를 등록한다.

- 이름과 설명은 장비 사양에 근거해 사용자가 정한다.
- AI는 이 목록 안에서만 모드를 고른다.

## 3. 로그 넣기 (세 탭 공통)

1. 왼쪽 '가져올 파일'에 TXT/LOG 파일을 끌어 놓거나 '파일 추가…'를 누른다.
2. **수집 세션**을 고른다. 모르면 '모름'을 고르고, 나중에 확인 질문에 답한다.
   - 같은 시점에 여러 컴포넌트에서 수집 → '같은 수집 세션'
   - 다른 시점에 재현·반복 수집 → '서로 다른 수집 세션'
3. 필요하면 로그 역할(컴포넌트 이름)과 FW 버전을 적고 **가져오기**를 누른다. 진행 중에 취소할 수 있다.

알아 둘 점:

- 파일당 10MB까지 가져올 수 있다. 한 번에 가져오는 총 용량 한도는 설정에서 바꾼다.
- 원본 파일은 바꾸지 않는다. 앱은 읽기 전용 사본과 SHA-256을 보관한다. 같은 내용의 파일은 다시 저장하지 않는다.
- 아래 뷰어에서 필터로 찾고, 행을 고르면 원본 행이 보인다.
- 로그 형식은 범용 예시 프로파일 3개와 '원문(한 줄 = 이벤트 하나)'으로 읽는다. 장비 고유 형식은 `configs\parser_profiles\`에 프로파일을 더해야 한다.

## 4. 정상 로그 학습

1. 로그를 넣고 제목을 적고 **저장**한다.
2. **운전 모드**를 고른다. 'AI로 추정'을 눌러도 되지만, 맞는지 보고 **확인함**을 직접 표시해야 한다.
3. **정상 판정 근거**를 적는다(승인 필수).
4. **패턴 후보 만들기**를 누른다. 같은 모드의 승인된 정상 사례와 비교해 후보를 만든다.
   - 후보 종류: 필수, 선택, 순서 제약, 독립, 반복, 미분류
   - 로그가 1개뿐이면 '미분류'다. 필수와 선택을 가르려면 로그가 2개 이상 필요하다.
   - 순서가 로그마다 다른 이벤트는 '독립'으로 나온다. 순서가 달라도 비정상이 아니다.
5. 후보마다 승인·거부·보류를 고른다. **필수와 순서 제약은 사용자가 승인해야 확정된다.**
6. 'AI 초안 만들기'(선택): AI 설명과 빠진 정보 질문을 만든다. 모두 '제안' 상태다.
7. **AI 확인 질문**에 답한다. 모름·건너뛰기를 고를 수 있다. 필수 질문이 남아 있으면 승인할 수 없다.
8. **승인**. 승인한 사례만 분석에 쓰인다.

## 5. 비정상 로그 학습

1. 로그를 넣고 저장한다.
2. **진단 가이드 첨부**(필수, TXT/MD). 제목 줄(예: `## 오류 증상`, `## 가능한 원인`)을 찾아 항목으로 나눈다. 제목이 없으면 전체가 '참고'가 된다. 이때는 'AI로 다시 분류'를 누른다. AI는 원문 조각에 항목 이름만 붙이고, 새 문장을 쓰지 않는다.
3. **대응 매뉴얼 첨부**(선택, TXT/MD). 대응 절차(단계별), 주의사항, 상위 지원 기준으로 나눈다.
4. '가이드에서 증상·기준 채우기'를 누르고 내용을 확인한다. 오류 증상과 판정 기준은 승인 필수다.
5. **원인 확정 여부**를 고른다(확정·추정·모름). 원인을 몰라도 등록할 수 있다.
6. 항목마다 승인·거부를 고르고 **승인**한다. 로그의 오류 코드가 문서에 그대로 나오면 '가이드-로그 연결'로 표시된다. 앱은 오류 코드에 뜻을 붙이지 않는다.

## 6. 신규 로그 분석 — "무엇을 하면 되나"

1. 로그를 넣는다. 운전 모드를 고르고 확인한다(모르면 '모름').
2. **분석 실행**. 진행 중에 취소할 수 있다.
3. 결과를 읽는다.
   - **권장 대응**(맨 위): 비슷한 승인 비정상 사례의 **승인된 대응 매뉴얼**에서 가져온 주의사항과 절차, 그리고 출처.
     - 매뉴얼이 없으면 진단 가이드의 해결 방법을 보여 준다.
     - 둘 다 없으면 "등록된 대응 방법 없음"이다.
     - **AI는 새 조치를 만들지 않는다.**
   - **결과 분류**: 아래 네 가지는 서로 독립이다. '찾은 이상 없음'은 정상이라는 판정이 아니다.
     - 정상 패턴 일치
     - 이상 수준
     - 기존 비정상 사례
     - 근거 충분성
   - **근거 표**: 결정론 결과와 사례 검색 결과. 두 번 누르면 원본 로그 행으로 간다. 유사도 점수는 순위 점수이고 확률이 아니다.
   - **AI 원인 가설**: 관측 사실, 가설(반대 근거 포함), AI가 정리한 대응 순서(매뉴얼 근거만), 추가 확인 절차, 판단 불가 항목.
     - 매뉴얼 근거가 없는 확인 절차에는 "AI 제안 — 매뉴얼 근거 없음"이 붙는다.
     - 근거 키가 유효해도 해석은 틀릴 수 있다. **반드시 검토한다.**
4. **보고서 저장**(JSON·HTML). 저장 위치: `분석\R-xxxx\`
5. 이 로그를 학습에 쓰려면 **정상/비정상 학습 사례로 등록**을 누른다. 해당 탭에 초안이 열린다.

## 7. 관리

| 메뉴 | 하는 일 |
|---|---|
| 학습 사례 관리 | 목록·개정 이력·열기·보관·보관 해제·초안 삭제. 승인된 사례를 고치려면 사례 화면에서 '수정 시작'을 누른다. 다시 승인할 때까지 분석에서 빠지고, 이전 개정본은 보존된다. |
| 분석 이력 | 저장된 분석 다시 보기, 보고서 저장 |
| 승인된 지식 보기 | 분석에 실제로 쓰이는 승인 패턴·가이드·매뉴얼 항목 |
| 백업 및 복원 | 백업 zip 만들기와 복원. 복원할 때 지금 데이터는 지우지 않고 옮기며, 복원 직전 상태도 따로 백업한다. 복원 뒤에는 앱을 다시 시작한다. |
| 설정 | Ollama 주소(이 PC 안 주소만)·모델·시간 제한, 가져오기 한도, 데이터 폴더 |

## 8. 알려진 제약

- 실제 장비 로그 형식은 아직 검증하지 않았다. 범용 프로파일에 맞지 않으면 원문 파서로 읽는다(타임스탬프 기준 '모름').
- 바이너리 로그(예: 바이너리 CAN 로그)는 받지 않는다. 텍스트로 바꾼 로그만 넣는다.
- 대응 매뉴얼은 TXT/MD만 받는다. PDF 등은 승인 패키지 목록이 정해진 뒤 검토한다.
- DB는 입력 로그의 약 5~6배 크기다.
- 작은 AI 모델은 근거 키를 빠뜨려 검증에 걸릴 수 있다. 그때는 AI 결과를 저장하지 않고 '검증 실패'로 표시한다.
