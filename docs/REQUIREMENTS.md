# 요구사항 추적표와 검토 — Local Log Analyzer

- 기준 문서: [DEV_PLAN_v0.2_R01.md](DEV_PLAN_v0.2_R01.md) (LLA-DEV-PLAN-001 v0.2 R01). 이 표는 계획서를 대신하지 않는다. 충돌하면 계획서가 이긴다.
- 계획서 이후 사용자가 더한 요구사항은 변경 요청(CR)으로 §1.16에 둔다. 현재 CR-01(대응 매뉴얼·권장 대응), CR-02(화면 디자인·가독성, 기능 변경 없음), CR-03(다른 PC 무설치 실행) 3건.
- 작성: 2026-11-16, Phase 1 착수 시점.
- 상태 표기 (2026-11-17 Phase 9 기준으로 갱신)
  - **구현**: 코드와 자동화 테스트로 충족함 (검증 열의 테스트 참조)
  - 아래는 Phase 1 당시 표기
  - **P1 구현**: 이번 Phase 1 코드와 테스트로 충족함
  - **P1 기반**: Phase 1에서 스키마·설정·구조만 준비함. 기능은 표시된 Phase에서 구현
  - **Pn**: 해당 Phase에서 구현 예정. 아직 코드 없음
  - **미정**: 사용자 답이 필요함(§3 질문 참조)
- 검증 열의 `T-…`는 [TEST_PLAN.md](TEST_PLAN.md)의 시험 ID, `test_…`는 실제 테스트 파일이다.

### 1.18 변경 요청 CR-03 — 다른 PC 무설치 실행 (2026-11-17 사용자 요청)

> 사용자 요청 요지: 개발 환경이 아닌 다른 PC에서 앱을 실행할 때 **아무것도 설치할 필요가 없어야** 한다. 질문 "AI 기능까지 설치 없이가 필요한가?"에 사용자가 **"Ollama 휴대용 동봉"**(앱 코드는 프로세스를 실행하지 않음)을 골랐다.
> 계획서 §2.1은 "AI: Ollama 로컬 서버"만 정하고 설치 방식은 정하지 않았다. 아키텍처 규칙(`app/` 안 프로세스 실행 금지)은 그대로 지킨다.

| ID | 요구사항 | 상태 | 검증 |
|---|---|---|---|
| DEP-01 | 앱 폴더를 복사만 하면 실행된다. Python·Qt·Visual C++ 런타임을 따로 설치하지 않는다 | 구현 | DLL 의존성 조사(폴더 밖 비기본 DLL 0개), 빈 환경 변수·한글 경로 실행 |
| DEP-02 | 휴대용 Ollama와 모델을 배포 폴더에 넣는다. 빌드 PC의 설치본·받아 둔 모델을 복사하고 인터넷에서 받지 않는다. 트레이 앱·자동 업데이트 제외, 모델 해시 확인 | 구현 | `unit/test_bundle_ollama` |
| DEP-03 | 더블클릭 시작 파일: 127.0.0.1 바인딩, 클라우드 끔, 앱 폴더 모델만, 이미 실행 중인 Ollama는 재사용, 끄기 파일은 휴대용 서버만 끔 | 구현 | `unit/test_bundle_ollama`, 실제 실행(11435 포트) |
| DEP-04 | 배포 기본 모델을 동봉한 모델로 미리 설정(값이 비어 있을 때만) | 구현 | `unit/test_bundle_ollama` |
| DEP-05 | AI 서버가 꺼져 있으면 상태 표시줄에서 시작 파일을 안내 | 구현 | `ui/test_main_window` |

남은 위험:

- GPU 라이브러리를 모두 넣으면 약 6.5GB다. 사내 PC의 GPU가 확인되면 `-OllamaGpu cpu|nvidia`로 줄인다.
- 실행 파일·cmd는 서명하지 않았다. 사내 백신·SmartScreen 정책 확인이 필요하다.
- 모델 라이선스(Gemma 사용 약관 등)의 사내 사용 승인은 사용자가 확인한다.

### 2.3 구현상 위험

| # | 위험 | 대응 |
|---|---|---|
| K-1 | **CPU 전용 추론 속도.** 7~8B 양자화 모델을 CPU로 돌리면 초당 몇 토큰 수준이라 분석 한 번에 몇 분이 걸릴 수 있다. | 근거 패키지 크기 제한, 스트리밍, 취소. Phase 7 전에 사내 PC에서 실제 속도를 측정한다. |

| K-3 | **로그 형식 미확인.** 샘플 없이 만든 파서는 추측이 된다. | 범용 파서는 정규식 프로파일로만 동작하게 하고, 실제 형식은 프로파일로 추가한다. Phase 2 전에 샘플이 필요하다(Q4). |

| K-6 | **사내 프록시.** `HTTP_PROXY` 환경 변수가 있으면 httpx가 localhost 요청도 프록시로 보낼 수 있다. | httpx를 `trust_env=False`로 만든다(Phase 1 구현). |
| K-7 | **SQLite 버전 차이.** STRICT 테이블은 3.37 이상, FTS5는 빌드 옵션이 필요하다. | 시작할 때 기능을 검사한다(Phase 1 구현). 실행 파일에는 SQLite가 함께 들어간다. |
| K-8 | **이벤트 행 수.** 10MB 파일 하나가 약 10만 줄이면 10개 파일은 100만 행이다. | Phase 2에서 일괄 삽입과 색인을 쓰고 성능 테스트(T-PERF-01)를 한다. |
| K-9 | **개발 PC 한정: MSIX 가상화.** Claude 데스크톱 앱 안에서 실행한 프로세스가 `%LOCALAPPDATA%`에 쓰면 앱 전용 공간으로 가상화된다. | 테스트는 `LLA_HOME` 환경 변수로 임시 폴더를 쓴다. 사용자가 직접 실행할 때는 영향이 없다. |
| K-10 | **바이너리 CAN 로그.** 검토 의견은 CAN 로그를 언급하는데, 계획서 입력은 TXT/LOG뿐이다. | 텍스트로 변환된 CAN 로그만 범위에 넣는다. 바이너리 형식이 필요하면 요구사항 추가가 필요하다(Q4). |
| K-11 | **PySide6 라이선스(LGPL).** 사내 배포할 때 고지가 필요하다. | Phase 9 패키징 때 고지 파일을 포함한다. |
