# CR-16 설계 — 확인 흐름 손질 + 참고 자료의 판정 설명을 판정에 쓰기 (2026-11-23)

사용자가 `samples/직접시험_다중챔버`로 앱을 직접 시험해 보고 남긴 다섯 가지.

1. 분석 결과 창에서 로그를 하나씩 눌러 '확인 결과 남기기'를 고르는 대신 **분석 결과 목록에 바로 단추**. 확인 결과 남기기에서 체크한 뒤 무엇을 해야 할지 모르겠음.
2. ③ 상세 확인으로 가면 '분석한 로그' 목록의 파일 이름이 거의 사라짐(`시...g`). 줄지 않게, 처음부터 줄이지 말기.
3. ③에서 정상·비정상 학습 사례로 등록하면 학습 탭으로 넘어가는 것이 불편함.
4. 한 화면에서 다른 화면으로 옮겨 갔을 때 **뒤로 가기**로 앞 화면에 돌아가기.
5. 학습한 로그가 적어도 **참고 자료에 명확한 설명**(엑셀에 '이 로그는 에러다·정상이다')이 있으면 판단을 더 잘해야 함.

판정 원칙은 그대로다: 판정은 코드(규칙 + 사례 기억 + 기준), AI(LLM)는 판정에 넣지 않는다. 뜻을 만들지 않는다(참고 자료 글자 그대로).

## 1. 확인 결과를 목록에서 바로 (UX-01)

- ②·③ 결과 목록에 **'확인' 칸**: `[정상] [비정상]` 단추. 누르면 그 로그(같은 수집 세션 묶음이면 묶음 전체)를 바로 사례로 저장한다.
  - 정상: 바로 저장.
  - 비정상: 작은 창에서 판단 근거(꼭)·메모를 받아 저장. 비정상 사례는 판단 근거가 있어야 승인되는 규칙(CR-06) 그대로.
  - 저장한 줄은 그 단추가 눌린 모양으로 남는다. 다른 쪽을 누르면 바꿔 저장한다.
- ② '확인 결과 남기기' 상자: 라디오 + '사례로 저장' 대신 **'정상이었음으로 저장'·'비정상이었음으로 저장…'** 단추 두 개. 글 칸은 메모(정상) / 판단 근거(비정상). 비정상인데 글 칸이 비었으면 같은 창으로 근거를 받는다.
- 목록·상자·③ 단추는 같은 저장 함수(`LogEntryService.save_group`)를 쓰고 같은 상태를 보인다(한쪽에서 저장하면 다른 쪽도 바뀜).

## 2. ③ 목록 폭 (UX-02)

- ②·③ 목록을 같은 폭(400px)으로 시작하고, 한쪽에서 폭을 바꾸면 다른 쪽도 같게 맞춘다.
- 파일 칸은 이름 길이만큼(가운데 줄임 없이), 결과 칸이 남는 폭을 쓴다.
- 목록이 넓어진 만큼 ② 두 칸 나란히 배치 문턱을 1300px → 1100px.

## 3. ③에서 사례 저장은 그 자리에서 (UX-03)

- ③ 아래 단추를 '정상이었음으로 저장'·'비정상이었음으로 저장…'으로 바꾸고 1과 같은 저장을 한다. 학습 탭으로 넘기지 않는다.
- 학습 탭으로 넘기던 경로(`register_requested`)는 없앤다. 자세히 적고 싶으면 학습 탭 ③ 저장된 로그에서 고친다.

## 4. 뒤로 가기 (UX-04)

- 메인 창이 화면 이동 이력(작업 화면 + ①②③ 단계)을 기억한다. 왼쪽 메뉴 맨 위 **'‹ 뒤로'** 단추, `Alt+←`, 마우스 뒤로 단추.
- 이력이 없으면 단추가 흐리다. 뒤로 가기로 옮긴 것은 이력에 다시 쌓지 않는다. 최대 50개.
- 대화 상자(학습 사례·분석 이력·참고 자료·판단 기준·설정)는 닫으면 돌아오므로 이력에 넣지 않는다.

## 5. 참고 자료의 판정 설명을 판정에 쓰기 (RJ-01~07)

지금 참고 자료는 로그에 나온 코드의 설명을 **보여 주기만** 하고 판정에는 쓰지 않는다. 문서가 '이 로그는 에러/정상'이라고 분명히 말하면 학습량과 상관없이 판정에 쓴다.

- **RJ-01 판정 칸 읽기**: 표 머리글에 판정·판단·구분·분류·정상여부·이상여부·에러여부·오류여부·심각도·등급·severity·verdict·judgment·classification이 들어 있으면 '판정 열'. 글 문서는 코드 머리글 블록 안 '판정:'·'구분:' 줄. 값은 **문서 글자 그대로** 저장한다(마이그레이션 0009 `reference_entries.judgment`, 스키마 9). 초안일 때 참고 자료 관리에서 열 역할('판정 열')과 항목 '판정' 칸을 고칠 수 있다.
- **RJ-02 낱말 → 쪽**(코드 고정 목록, 문서의 분류 낱말만 읽음):
  - 비정상: 에러·오류·이상·비정상·고장·불량·알람·점검 필요·조치 필요·error·fault·fail·abnormal·alarm·critical·fatal·ng
  - 정상: 정상·문제없음·무시·무해·정보·normal·ok·ignore·benign·info
  - 그 밖(경고·주의·상황에 따라 등), 두 쪽이 섞임, 부정('아님'·'not')은 **판정에 쓰지 않고** 화면에 '판정에 안 씀'으로 보인다.
- **RJ-03 로그에서 찾기**: 코드처럼 생긴 항목은 지금처럼(오류 코드 칸·메시지 낱말). 코드처럼 생기지 않은 4자 이상 항목(예: `NOTICE flag=TEST-FK`)은 메시지에 그 글이 그대로 있으면(대소문자·공백 차이 무시, 앞뒤 낱말 경계) 맞춘다. 참고 자료 칸에도 보인다.
- **RJ-04 판정에 쓰기**: 규칙 → 사례 기억 → **참고 자료 판정** → 엔지니어 기준(CR-15) 순서.
  - 비정상으로 적힌 항목이 로그에 나오면 → 비정상 의심(승인된 규칙 위반은 그대로). 정상 로그를 아직 학습하지 않았어도.
  - 정상으로 적힌 항목이 나온 줄의 근거는 '문제없음'으로 보고, 규칙이 의심한 강한 근거가 모두 그런 줄이면 → 정상.
  - 판정 이유: `참고 자료 「문서 · 위치」에 'TEST-…'이(가) '에러'로 적혀 있음(로그 12행)`.
  - 엔지니어 기준이 같은 근거에 있으면 엔지니어 기준이 이긴다(뒤에 적용).
- **RJ-05 스스로 점검**: 확인된 사례 로그에 그 항목이 나온 횟수를 센다. 비정상으로 적힌 항목이 확인된 정상 로그에 2번 이상, 비정상 로그보다 많이 나왔으면(정상으로 적힌 항목은 반대) 이번 판정에 쓰지 않고 이유를 남긴다. 승인된 문서는 바꿀 수 없으므로 끄지 않고 건너뛴다. 확인 로그가 쌓일수록 잘못 적힌 항목이 걸러진다.
- **RJ-06 질문**: 참고 자료가 판정을 준 근거는 '판단을 돕는 질문'에서 묻지 않는다.
- **RJ-07 측정**: `evaluate_learning.py --reference <표 파일> --train-limit N`. ① 학습 때 없던 알림을 표로만 알려 줌 ② 학습 로그를 적게.

## 7. 구현 메모·결과 (2026-11-23)

- 목록 '확인' 칸은 표 칸 위젯이라 내용 맞춤 폭에 안 잡혀, 단추 최소 폭(글자 + 여백)으로 칸 폭을 잰다. 저장한 쪽은 눌린 모양(정상 초록·비정상 주황).
- ③ 아래 '방금 저장' 글은 단추 줄 위 한 줄. 아래 줄에 두면 1366 폭에서 왼쪽 목록이 400 → 324px로 밀렸다(이 글이 폭을 요구).
- 참고 자료 판정은 `app/analysis/reference_judgment.py`. 비정상으로 적힌 줄에 결정론 근거가 없을 때도 `REFERENCE:<코드>` 특징을 남겨,
  엔지니어 기준이 그 근거를 모른 채 판정을 내리지 못하게 했다(엔지니어 기준은 같은 근거에 답했을 때만 이긴다).
- 스스로 점검 개수는 앱이 켜져 있는 동안 (DB, 사례 상태, 항목)으로 기억한다.
- 측정(학습 → 시험 하나씩 분석·확인, AI 없이, 표 `samples/참고자료_판정표_예시.xlsx`):
  - 학습 100 → 학습 때 없던 FK 알림 8개 세트: 최종 92% → **98%**(FK 8/8, 첫 번째부터). 남은 하나는 기판 빠짐(근거 없음, 알려진 한계).
  - **학습 10개**(정상 7·비정상 3) → FK 8·FA 섞인 50개: 최종 76% → **86%**, 앞 절반 68% → 80%.
  - 학습 10개 → 기본 시험 세트(코드 있는 고장은 규칙이 이미 잡음): 90% = 90%(질문 46 → 43). 표에 없는 고장은 표가 도울 수 없다.
