# Local Log Analyzer — UI 개편용 앱 설명서

> 이 문서는 다른 AI(예: ChatGPT)에게 **UI 아이디어를 받으려고** 쓴 설명서입니다. 앱이 무엇을 하는지, 누가 어디서 쓰는지,
> 지금 화면이 어떻게 생겼는지, 바꾸면 안 되는 것이 무엇인지를 담았습니다. 맨 아래에 그대로 붙여 쓸 수 있는 요청문이 있습니다.
> 기준: 앱 v0.4.1(2026-11-19) + 그 뒤 '예상 에러 메시지' 칸. 화면의 로그·코드는 모두 가상 데이터(TEST-)입니다.
> **2026-11-22 이후 화면은 단계별 구성(CR-12)으로 바뀌었다** — `docs/CR12_단계별_화면_설계.md`. 아래 §5는 그 전 모습이다.

---

## 1. 한 줄 요약

장비 로그 파일을 넣으면, **사람이 미리 승인해 둔 정상·비정상 로그와 비교**해서 "이 로그가 정상과 무엇이 다른지, 무엇을 하면 되는지"를
근거(원본 로그 행)와 함께 보여 주는 **Windows 데스크톱 앱**입니다. 인터넷 없이 사내 PC 안에서만 돌고, AI(로컬 모델)는 보조 의견만 냅니다.

## 2. 누가, 어디서 쓰나

- **주 사용자: 현장 CS 엔지니어.** 장비 옆 노트북(대략 1366×768 ~ 1920×1080)에서 서서 또는 좁은 자리에서 봅니다.
- **앱을 처음 쓰는 사람이 많습니다.** 설명서 없이도 다음 할 일이 보여야 합니다.
- 보조 사용자: 정상·비정상 로그를 모아 학습시키는 기술 담당자(같은 앱).
- 사내 PC는 인터넷이 막혀 있습니다. 모든 처리는 PC 안에서 합니다.
- 언어: 한국어 화면.
- 성공 기준: 로그를 넣고 **몇 분 안에** 무엇이 이상한지와 승인된 대응 절차를 찾는 것.

## 3. 기술 제약 (UI 아이디어가 지켜야 할 것)

| 항목 | 내용 |
|---|---|
| 플랫폼 | Windows 10/11 데스크톱, **Python 3.11 + PySide6(Qt Widgets)** 고정. 웹·Electron으로 바꾸지 않음 |
| 꾸밈 방법 | Qt 위젯 + **QSS(Qt 스타일시트)** 한 파일(`app/ui/theme.py`)의 색·크기 토큰. 위젯은 역할 속성(role·tone·variant)만 단다 |
| 자원 | **외부 폰트·아이콘·이미지 다운로드 불가**(오프라인). Windows 기본 글꼴(맑은 고딕, Segoe UI, Consolas)만 |
| 기능 | **기능은 바꾸지 않고** 배치·정보 위계·시각만 바꾼다(필요하면 화면 나눔·탭·접기·대화상자 등은 바꿔도 됨) |
| 접근성 | 색만으로 상태를 말하지 않는다(글자 라벨 함께). 본문 10.5pt 이상, 대비 WCAG AA |
| 화면 크기 | 1366×768에서도 핵심 결과가 보여야 함, 1920×1080에서는 공간을 낭비하지 않아야 함 |
| 그 밖 | 실제 장비의 오류 코드 뜻·사양을 화면 예시에 지어내지 않는다(예시는 TEST-E001 같은 가상 코드) |

## 4. 꼭 알아야 할 개념

- **로그 파일**: 장비가 남긴 TXT·LOG. 형식이 제각각이라 앱이 자동으로 시각·레벨·구성요소를 읽어 '이벤트'로 나눈다.
- **정상 로그 / 비정상 로그**: 사용자가 '로그 입력' 탭에서 파일마다 고르고 저장한다. **저장 = 승인 = 바로 학습**에 쓰임.
- **동작 메모**: 그 로그가 어떤 동작이었는지(선택). **판단 가이드**: 비정상일 때 무엇을 보고 에러로 판단했는지(선택).
- **비슷한 정상 로그와 비교**: 새 로그를 분석하면 저장된 정상 로그 중 가장 비슷한 것들과 비교해, 빠진 메시지·횟수·순서·간격·
  값 범위·상태값 차이를 '의심' 근거로 찾는다.
- **근거 키**: 분석 근거마다 붙는 번호(EV-0001…). 화면·보고서·AI 의견이 같은 키로 서로 가리킨다. **두 번 누르면 원본 로그 행으로 이동**.
- **결과 분류(서로 독립된 4칸)**: 정상 패턴 일치 / 이상 수준(찾은 이상 없음·비정상 의심·규칙 위반) / 기존 비정상 사례 / 근거 충분성.
- **권장 대응**: 비슷한 승인 비정상 사례에 사람이 붙여 둔 대응 매뉴얼·가이드 항목만 보여 준다. **AI가 만들지 않는다.**
- **예상 에러 메시지**: 비정상으로 보인 로그에서 문제로 보이는 **원문 줄**을 묶음별(에러로 기록된 줄·정상과 다른 줄·처음 보는 경고·
  실패 줄·빠진 메시지)로 보여 준다.
- **참고 자료**: 사용자가 올린 오류 코드표·설명 문서(XLSX·PDF·DOCX 등). 로그에 나온 코드가 거기 있으면 그 글을 그대로 보여 준다.
- **AI 분석 의견**: 로컬 모델(Ollama, 예: gemma3:4b)이 근거만 보고 정리한 관측 사실·원인 가설·비정상일 가능성(%).
  **AI 추정치, 사용자 검토 필요**라고 늘 표시한다. 근거가 없는 문장은 앱이 버린다.
- **AI 질문**: 로그를 저장하면 AI가 그 로그를 보고 궁금한 점을 묻는다(답은 선택). 답은 다음 분석에 참고된다.

## 5. 지금 화면 구성

### 5.1 메인 창

```
┌ 메뉴: 관리(M) | 도움말(H) ───────────────────────────────────────────────┐
│ [처음 사용 안내 띠] 설정에서 AI 모델 고르기 / F1 사용 가이드 / 연습 파일 위치          │
├ 탭: [로그 입력] [신규 로그 분석] ──────────────────────────────────────────┤
│  (탭 내용: 왼쪽 로그 패널 | 오른쪽 작업·결과 영역, 가운데 경계선으로 너비 조절)          │
├ 상태 표시줄: 데이터 폴더 · DB 스키마 · SQLite · Ollama 연결 상태 · [다시 확인] ─────┤
```

- **관리 메뉴**: 학습 사례 관리 · 분석 이력 · 참고 자료 관리 · 승인된 지식 보기 · 설정 · 백업 및 복원
- **도움말 메뉴**: 사용 가이드(F1, 앱 안 HTML) · 연습용 예제 폴더 열기 · 정보 · 데이터 폴더 열기

### 5.2 공통 왼쪽 패널 (두 탭이 같은 부품을 씀)

위에서 아래로:
1. **끌어 놓기 칸**: "로그 파일을 여기로 끌어 놓거나 '파일 추가…'" — 넣으면 **바로 가져와** 목록에 올라감
2. **가져오기 옵션**(접힘): 수집 세션(같은 시점 여러 컴포넌트 / 다른 시점 / 모름) · 세션 이름 · 파서 · 로그 역할 · FW 버전
3. 진행 막대 + [가져오기 취소], 가져오기 결과 한 줄(가져온·이미 있던·거부 개수와 이유)
4. **올라온 로그 (N개)** 표: 파일 · (분석 탭만) 분석 결과 · 세션 · 인코딩 · 줄 · 이벤트 · 타임스탬프 · 파서 · 역할
5. [선택 파일을 이 목록에서 빼기] [목록 비우기]
6. **로그 원문 보기**(접힘): 이벤트 표(파일별, 필터·원문 보기) / 세션 타임라인(여러 파일을 시간순) 탭

### 5.3 '로그 입력' 탭 (학습시키기)

오른쪽 영역(세로 스크롤):
1. **진행 순서 안내 띠**: ① 끌어 놓기 → ② 목록에서 고르기(여러 개 가능) → ③ 정상/비정상(필수)·메모·판단 가이드(선택) → ④ 저장
2. **가져온 로그** 표: 파일 · 구분(정상/비정상/—) · 동작 메모 · 상태(저장 전·입력 중·저장됨)
3. **선택한 로그 설명** 카드: 선택 요약 / 구분 [정상] [비정상] / 메모 칸 / (비정상일 때) 판단 가이드 칸 + **이 로그에서 에러로 보이는 줄**
   목록 / [저장 (바로 학습에 씀)] [자세히 편집…]
4. **AI 질문** 상자: AI가 남긴 질문(추측 확인·질문), [맞음] [틀림] [모름] / 글로 답하기 / 건너뛰기 / 다시 묻기
5. **저장된 로그** 표: 파일 · 구분 · 동작 메모 · 저장 시각 (두 번 누르면 위 목록으로 불러와 고침)

동작: 다른 줄로 옮기거나 탭을 바꾸면 정상/비정상을 고른 입력은 자동 저장. '자세히 편집'은 예전 학습 화면(가이드·매뉴얼 첨부, 확인 질문, 패턴)을 별도 창으로.

### 5.4 '신규 로그 분석' 탭 (분석하기)

왼쪽: 공통 패널. **'분석 결과' 칸**에 로그마다 결과(예: "비정상 의심 · AI 75%", "이상 못 찾음")가 적히고,
**목록에서 로그를 고르면 오른쪽에 그 로그의 결과**가 나온다(드롭다운 없음). 마우스를 올리면 결과 분류와 예상 에러 메시지 앞 줄.

오른쪽 영역(세로 스크롤, 위에서 아래로):
1. 진행 순서 안내 띠
2. **상황 글 칸**: "이번 로그 상황을 편하게 적어 주세요(선택)" + [AI로 정리] + 정리된 내용
3. 칸으로 직접 고치기(접힘): 운전 조건
4. [ ] AI 원인 가설도 만들기
5. **[분석 실행 (N개)]**(결과가 모두 있으면 '모두 다시 분석') [취소] + 진행 막대("로그 2/5 분석 중…")
6. **결과 — 파일 이름 · R-번호** (제목) + "왼쪽에서 다른 로그를 고르면 그 결과가 보입니다"
7. **권장 대응** 카드 (도장: 매뉴얼 근거 / 가이드만 / 대응 없음) + 절차 목록 ← **결과 맨 위에 있어야 함(요구사항)**
8. **예상 에러 메시지** 카드 (비정상으로 보인 로그만): `[에러로 기록된 줄] 4행 ×2  원문…` + 이유 줄
9. **참고 자료** 카드: 로그에 나온 코드 중 참고 자료에 있는 것(명칭·설명·원인·조치 원문), 관련 문서 문단
10. **결과 분류** 4칸(표제란처럼 라벨 칸 한 줄): 정상 패턴 일치 · 이상 수준 · 기존 비정상 사례 · 근거 충분성
    + "유사도 점수는 순위 점수이며 진단 확률이 아닙니다"
11. **근거** 표: 근거 키 · 계층(결정론/사례 검색/AI) · 종류 · 내용 (두 번 누르면 원본 행)
12. **AI 분석 의견** 카드: 비정상일 가능성 %(색 + 글자) · 관측 사실 · 원인 가설(가능성 %) · 대응 순서(승인 근거만) · 추가 확인 절차 · 판단 불가
13. 메모(어느 정상 로그와 비교했는지 등)
14. [보고서 저장 (JSON·HTML)] [정상 학습 사례로 등록] [비정상 학습 사례로 등록]

로그가 여러 개면 로그마다 따로 분석한다(같은 수집 세션으로 가져온 파일은 함께).

### 5.5 관리 메뉴의 대화상자

- **학습 사례 관리**: 저장된 사례 목록·상태(초안·정보 필요·검토 요청·승인·반려·보관)·검토
- **분석 이력**: 지난 분석(R-번호) 목록, 결과 다시 보기, 보고서
- **참고 자료 관리**: 문서 올리기(TXT·MD·XLSX·PDF·DOCX), 항목 미리보기, 문서 단위 승인·보관·삭제
- **승인된 지식 보기**, **설정**(데이터 폴더, Ollama 주소·모델, 가져오기 한도), **백업 및 복원**

## 6. 대표 사용 흐름

1. **처음 학습**: 로그 입력 탭에 정상 로그 수십 개와 비정상 로그 몇 개를 끌어 놓음 → 목록에서 여러 개 골라 '정상' → 저장 →
   비정상은 하나씩 골라 '비정상' + 판단 가이드 → 저장 → (선택) AI 질문에 답함
2. **현장 분석**: 신규 로그 분석 탭에 문제 로그 1~5개를 끌어 놓음 → (선택) 상황 한 줄 → 분석 실행 →
   왼쪽 목록에서 '비정상 의심' 로그를 고름 → 권장 대응 · 예상 에러 메시지 확인 → 근거를 두 번 눌러 원본 행 확인 → 보고서 저장
3. **배운 것 쌓기**: 분석한 로그를 '비정상 학습 사례로 등록' → 로그 입력 탭으로 넘어가 판단 가이드를 적고 저장

## 7. 화면에서 반드시 지켜야 할 것

- **권장 대응은 결과 맨 위**(요구사항 CR-01). 대응이 없으면 "등록된 대응 방법 없음"을 분명히.
- AI 내용은 늘 **"AI 추정치 · 사용자 검토 필요"** 표시. AI 제안과 승인된 지식(매뉴얼·참고 자료)을 시각적으로 구분.
- **유사도 점수는 확률이 아니다**라는 문구 유지. '찾은 이상 없음'은 '정상 판정'이 아님.
- 모든 결과에서 **원본 로그 행으로 한 번에 이동**(두 번 누르기)할 수 있어야 함.
- 상태는 색 + 글자(도장·라벨). 확정 표현("확실히 원인") 금지.
- 처음 쓰는 사람에게 **다음 할 일**이 보이게(진행 순서·막힌 이유).

## 9. 지금 화면에서 보이는 문제 (개발 중 관찰 — 사용자 불만의 정확한 내용은 따로 받을 것)

- **세로로 너무 깁니다.** 분석 탭 오른쪽에 상황 글 칸·실행 단추가 위에 있어, 1366×768에서는 결과가 첫 화면 아래에 있습니다(고르면 자동으로 내려가게 해 둠).
- **같은 로그 목록이 두 번** 보입니다. 로그 입력 탭에서 왼쪽 '올라온 로그'와 오른쪽 '가져온 로그'가 거의 같은 내용입니다.
- **정보 밀도·카드 수가 많습니다.** 분석 결과에 카드 6~7개 + 표 + 긴 안내 문장이 한 줄로 쌓여, 무엇부터 봐야 할지 흐립니다.
- **안내 문장이 깁니다.** 진행 순서 띠, 카드 제목 괄호 설명, 주의 문구가 많아 읽을 거리가 많습니다.

- 상태 표시줄·첫 실행 안내 띠가 늘 자리를 차지합니다.

## 10. ChatGPT에 붙여 쓸 요청문 (예)

```
아래는 Windows 데스크톱 앱(Python 3.11 + PySide6 Qt Widgets, QSS로만 꾸밈, 오프라인이라 외부 폰트·아이콘 불가)의 설명서야.
현장 CS 엔지니어가 노트북(1366×768~1920×1080)에서 장비 로그를 넣고, 정상 로그와 비교한 결과·권장 대응·예상 에러 메시지를
몇 분 안에 확인하는 도구야. 기능은 그대로 두고 UI만 새로 설계하고 싶어.

2) '로그 입력' 탭과 '신규 로그 분석' 탭의 새 배치를 제안해 줘. 1366×768 기준 ASCII 와이어프레임으로,
   각 영역에 들어가는 위젯(Qt 위젯 이름: QSplitter, QTabWidget, QListWidget, QTableWidget, QGroupBox, QToolButton 등)을 적어 줘.

   단, '권장 대응은 결과 맨 위', 'AI는 추정치 표시', '근거는 두 번 눌러 원본 행 이동'은 지켜 줘.
4) 색·글꼴·간격 토큰(QSS에 바로 쓸 수 있는 값)과 상태 표시(도장·라벨) 규칙을 제안해 줘. 색만으로 상태를 말하지 않게.
5) 시안 2~3개를 서로 다른 방향(예: 마스터-디테일 / 단계 마법사 / 대시보드형)으로 비교해 줘.
```
