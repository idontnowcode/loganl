### 1.1 모든 테스트에 걸리는 장치

- **외부 네트워크 차단**: `tests/conftest.py`가 모든 테스트에서 `socket.connect`와 `getaddrinfo`를 감싸, loopback이 아닌 주소로의 연결과 이름 조회를 예외로 막는다. 코드가 어디서든 PC 밖으로 나가려 하면 테스트가 실패한다(SEC-03, §12.5 "인터넷 차단 상태에서 정상 작동").
- **데이터 폴더 격리**: 모든 테스트는 `LLA_HOME`을 임시 폴더로 바꿔 실행한다. 실제 `%LOCALAPPDATA%\LocalLogAnalyzer`를 건드리지 않는다.
- **가짜 Ollama**: Ollama 응답은 `httpx.MockTransport`로 만든다. 같은 입력이면 같은 결과가 나와야 하므로 실제 모델에 기대지 않는다.
- **화면 테스트**: `QT_QPA_PLATFORM=offscreen`으로 창을 띄우지 않는다.

### 1.2 테스트 데이터 규칙

- 테스트 로그는 **가상 형식**으로 만든다. 파일 머리에 `# 가상 테스트 로그 — 실제 장비 형식·의미 아님`을 적는다.
- 오류 코드는 `TEST-E001`처럼 테스트용임이 드러나는 문자열만 쓰고, 뜻을 붙이지 않는다(§13-11).
- 실제 로그 샘플을 받으면 `tests/fixtures/real/`에 두되, 내용을 가린 것만 두고 출처를 README에 적는다(Q2·Q4 답에 따라).

### 1.3 회귀

- 코드를 바꿀 때마다 `uv run pytest` 전체를 돌린다(§13-14). Phase 보고서에 통과·실패·건너뜀 수를 적는다.
- DB 스키마를 바꾸면 이전 버전 DB에서 마이그레이션하는 테스트를 추가한다.

### Phase 2 (2026-11-17) — 로그 가져오기·파싱

- 명령: `uv run pytest` → **301 통과, 1 건너뜀, 0 실패**. 새 테스트: `test_decoding`(12), `test_parsers`(14), `test_importer`(17), `test_repositories`(6), `ui/test_log_import_panel`(5). 기존 테스트는 스키마 v2(마이그레이션 0002)에 맞춰 기대값을 고쳤다.
- 처음 돌렸을 때 실패 3건은 모두 **테스트 데이터** 문제였다. 고친 뒤 통과했다.
  - 머리 줄에만 시간대가 없음. 앱이 시간대 혼합을 ABSOLUTE_NO_TZ로 낮춰 판정한 것이 맞는 동작이었다.
  - 테스트가 머리 줄 인덱스를 잘못 셈.
  - CP949로 쓸 수 없는 문자(긴 줄표)를 테스트 로그에 넣음.
- **데이터 손실 없음** 검증(`assert_no_loss`): 빈 줄이 아닌 모든 원본 줄이 정확히 하나의 이벤트에, 원래 줄 번호로 들어 있는지 파서마다 확인한다. 여러 줄 이벤트 안의 빈 줄도 보존한다.
- **T-PERF-01** (`LLA_PERF=1`): 10MB 가상 로그 10개, 이벤트 1,417,480개를 **32.5초**에 가져왔다. DB 크기 **508MB**(입력의 약 5배). 원문(raw_text)과 메시지를 따로 저장하고 색인이 있어서다. 사내 PC 디스크 여유를 확인해야 한다(알려진 제약).
- 실제 장비 로그 형식은 **미검증**(Q4). 범용 예시 프로파일 3개와 원문 파서로만 시험했다.

### Phase 3 (2026-11-17) — 정상 로그 학습

- 명령: `uv run pytest` → **364 통과, 2 건너뜀(실제 Ollama·성능), 0 실패**. 새 테스트: `test_pattern_analyzer`(6), `test_ai_structured`(17), `integration/test_normal_learning`(9), `ui/test_normal_learning_page`(5).

### AI 의견이 검증에 실패하던 문제 (2026-11-19, 실사용 보고)

- 보고: 다른 PC에서 샘플을 넣고 분석하니 근거가 '본 적 없는 이벤트'로 채워지고, AI 의견이 "V-3: 없는 근거 키 ['0005', …, '001035', …]; V-9 …"와 영어 문장으로 검증에 실패.
- 원인: Ollama에 문맥 길이(num_ctx)를 주지 않아 기본값(Ollama 0.40, 약 2,000토큰)만 썼다. 본 적 없는 이벤트 25~30개가 든 진단 프롬프트는 약 5,400~7,400토큰이라 **앞부분(시스템 지시·분석 요약·키 안내)이 잘려** 모델이 뒤쪽 근거 원문만 보고 답했다(실측: 같은 프롬프트의 실제 토큰 7,437, 기본 설정으로 읽힌 토큰 2,051). 같은 입력을 고치기 전 코드로 돌리면 빈 응답 `{}`이 '통과'하기도 했다. 글 정리·가이드 항목 나누기·질문 만들기도 12,000~16,000자 프롬프트라 같은 잘림을 겪고 있었다.
- 고침: ① 요청마다 num_ctx를 글 길이에 맞춤(`ollama_client.context_size`, 4,096~16,384, 넘으면 보내지 않음) ② 진단 근거 목록을 중요한 것부터(이상 근거 → 대응·가이드 → 사례 → 본 적 없는 이벤트), 1만 자, 키 안내는 넣은 키만 ③ 어긋난 항목만 버리기(V-4·V-5·V-8·V-9·V-11, AI_POLICY §3) ④ 빈 응답 거부(V-1) ⑤ 비교할 정상 로그가 없으면 비정상 가능성을 매기지 않도록 프롬프트에 적음.
- 실제 gemma3:4b 확인(이 PC): 본 적 없는 이벤트 25개 + 값 튐(보고와 같은 모양) → 고치기 전 빈 응답, 고친 뒤 한국어로 값 튐 근거 키를 짚어 통과. 본 적 없는 이벤트만 30개·12개+값 튐·값 튐만, 제품군 5개 비정상 샘플(명시 오류·순서·누락·횟수), 비교 기준 없는 다른 제품군 로그 — 모두 통과(비교 기준이 없으면 가능성 매기지 않음). `LLA_LIVE_OLLAMA=1` 실제 모델 시험 3개 통과.
- 시험: 거부 대신 버리기로 바뀐 V-4·V-5·V-8·V-9 경우를 `integration/test_diagnosis`에서 '그 항목만 빠지고 나머지는 저장'으로 바꾸고, 빈 응답·문맥 길이·근거 순서·키 안내·버리기 단위 시험을 더함.
