# CR-12 단계별 화면 — 설계 (초안, 2026-11-22)

> 상태: **구현(2026-11-22)**. §9는 사용자가 '권장하는 대로'로 결정. 넓은 화면 두 칸은 결과 영역 1300px 이상(창 약 1700px 이상)에서.
> 출발점: 사용자 "화면이 너무 복잡한 것 같아서 단계별 구성" + GPT 시안 3장(`gptsample/`) + 검토 결과(아래 §2).
> 기능·판정 규칙은 바꾸지 않는다. 바뀌는 것은 화면 배치·정보 순서이고, 예외는 §9의 '정해야 할 것'에 따로 적었다.

---

## 1. 목표

1. 한 화면에 **할 일 하나**만 보이게 한다. 지금은 입력·실행·결과·근거·AI가 한 화면에 세로로 쌓여 있다.
2. 현장 엔지니어가 **판정 → 할 일 → 근거** 순서로 읽게 한다. 첫 결과 화면에서 스크롤 없이 판정·권장 대응·예상 에러가 보여야 한다(1366×768).
3. 학습(로그 입력)도 같은 단계 방식으로 맞춰, 두 작업이 같은 모양으로 읽히게 한다.
4. 지켜야 할 규칙은 그대로다: 권장 대응은 결과 맨 위, AI는 '추정치·사용자 검토 필요', 근거는 두 번 눌러 원본 행, 색 + 글자 라벨, 뜻은 지어내지 않음.

## 2. GPT 시안에서 가져올 것 / 고칠 것

| 가져올 것 | 고칠 것 |
|---|---|
| 단계 막대(①→②→③) | 시안의 코드 뜻·조치 문장('전압 범위 초과', 'TP1, TP2')은 지어낸 것 → 결정론 요약·승인된 글·AI(표시 달고)로만 채움 |
| ② 왼쪽 결과 목록 + 오른쪽 요약(판정 크게, 결과 칸, 권장 대응·예상 에러·근거 일부) | '운전 조건: 일반 운전' 선택 칸 → 뺌(CR-09) |
| ③ 상세: 근거 전체·AI 의견 접기·보고서 저장 | 이름 겹침: 메뉴 '로그 입력'(학습)과 단계 '① 로그 입력' → 단계 이름 '로그 넣기' |
| 왼쪽 메뉴(작업·데이터 관리·설정 묶음) | ③에 참고 자료·원본 로그 보기가 없음 → 넣음 |
| 상태 표시줄 유지 | 학습 화면 시안이 없음 → §5에서 설계 |
| 목록의 상태 표시(완료·비정상 의심) | 1366×768에서 카드 두 줄 → 좁으면 한 줄로 내림(§7) |

## 3. 전체 틀

```
┌ 메뉴: 관리(M) 도움말(H) ─────────────────────────────────────────────────────┐
├──────────────┬───────────────────────────────────────────────────────────────┤
│ 작업          │  [화면 제목]  한 줄 설명                                          │
│  ▸ 학습        │  ( ① 단계 )──>( ② 단계 )──>( ③ 단계 )        ← 단계 막대          │
│  ▸ 신규 분석   │ ─────────────────────────────────────────────────────────────  │
│ 데이터 관리    │                                                               │
│    학습 사례   │             단계 내용 (QStackedWidget 한 장)                      │
│    분석 이력   │                                                               │
│    참고 자료   │                                                               │
│ 설정          │  ─────────────────────────── [◀ 이전]        [다음 단계 ▶] ───   │
├──────────────┴───────────────────────────────────────────────────────────────┤
│ 상태 표시줄: 데이터 폴더 · DB 스키마 · Ollama 상태 · [다시 확인]                         │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **왼쪽 메뉴**(폭 180px 고정, 좁으면 160px): '학습'과 '신규 분석'은 오른쪽 화면을 바꾼다. '데이터 관리'·'설정' 항목은 **지금 대화상자를 그대로 연다**(이번 CR에서 화면으로 옮기지 않음).
- 위 '관리' 메뉴는 남긴다(키보드 Alt+M, 같은 동작). 시안의 '홈'은 넣지 않는다(내용이 정해지지 않음).
- **단계 막대**: 번호 원 + 이름 버튼 3개. 지금 단계는 강조색 채움, 갈 수 있는 단계는 흰 바탕, 아직 못 가는 단계는 흐리게 + 이유 툴팁("먼저 분석을 실행하세요").
  단계는 앞뒤로 자유롭게 오간다(입력을 고치러 ①로 돌아가도 결과는 남음).
- **아래 이동 줄**: 단계마다 기본 버튼 하나(강조색). 이전 단계 버튼은 왼쪽.
- 첫 실행 안내 띠: 지금처럼 위에 두되, 학습한 로그가 생기면 사라진다(지금 동작 유지).

## 4. 신규 분석 — 3단계

### ① 로그 넣기

```
 [i] 분석할 로그 파일을 넣으세요. 여러 개를 함께 넣을 수 있습니다.
 ┌ 끌어 놓기 칸 ─────────────────────────────────────────────┐
 │  로그 파일을 여기로 끌어 놓거나 [파일 추가…]  (TXT·LOG, 여러 개) │
 └──────────────────────────────────────────────────────────┘
 로그 파일 (5개)                       가져온 5 · 이미 있던 0 · 거부 0
 ┌──┬────────────┬──────────┬──────┬──────┬──────────┐
 │☑ │ 파일        │ 세션      │ 줄    │ 이벤트 │ 상태      │
 └──┴────────────┴──────────┴──────┴──────┴──────────┘
 [선택 빼기] [목록 비우기]          ▸ 가져오기 옵션(수집 세션·파서…)   ▸ 로그 원문 보기
 상황 메모(선택, 이번 분석 전체에)  [..........................................] [AI로 정리]
 [ ] AI 원인 가설도 만들기                                        [분석 시작 ▶]
```

- 표 열은 줄인다: 파일 · 세션 · 줄 · 이벤트 · 상태. 인코딩·타임스탬프·파서·역할은 툴팁과 '로그 원문 보기' 안으로.
- **체크 칸**(§9 결정 1): 기본은 모두 체크. 체크한 로그만 분석. 결과가 이미 있는 로그는 상태 '완료'.
- 상황 메모는 지금처럼 한 칸(이번 분석 전체에). '칸으로 직접 고치기(운전 조건)'는 메모 아래 접힘으로 유지.
- [분석 시작] → 바로 ②로 넘어가고, ②에서 로그마다 진행 상태가 바뀐다.

### ② 분석 결과 (판정과 할 일)

```
 ┌ 분석 결과 목록 (5) ─────┐ ┌ 결과 — P4_004.log · R-0001                 분석 2026-11-19 10:32 ┐
 │ 파일        상태  이상 수준 │ │ ┌──────────┐ ┌ 근거 요약 ───────────────────────────────┐ │
 │▶P4_004.log 완료 [비정상의심]│ │ │ ⚠ 비정상 의심 │ │ 오류 코드 줄 1 · 정상과 다른 값 1 · 빠진 메시지 0  │ │
 │ P4_005.log 완료 [비정상의심]│ │ └──────────┘ │ AI 비정상 가능성 75% (AI 추정치)                │ │
 │ P4_015.log 완료 [이상 못 찾음]│ │              └────────────────────────────────────────┘ │
 │ P4_021.log 분석 중…        │ │ [정상 패턴 일치: 일부] [기존 비정상 사례: 없음] [근거 충분성: 충분]        │
 │ P4_032.log 대기            │ │ ┌ 권장 대응 [매뉴얼 근거] ─────────┐ ┌ 예상 에러 메시지 ─────────────┐ │
 │                          │ │ │ 1. (승인된 매뉴얼 글 그대로)       │ │ [에러] 4행 ×2  원문…          │ │
 │                          │ │ │ 2. …                          │ │ [정상과 다른 값] 250행 원문…    │ │
 │                          │ │ └──────────────────────────────┘ └──────────────────────────┘ │
 └──────────────────────────┘ │                              [상세 확인 ▶]   [보고서 저장]     │
                              └──────────────────────────────────────────────────────────────┘
```

- **왼쪽 목록**: 파일 · 상태(대기 / 분석 중 / 완료 / 실패 / 취소) · 이상 수준 도장. 지금의 '분석 결과' 칸을 옮긴 것. 고르면 오른쪽이 바뀜.
- **판정 칸**(큰 도장): 이상 수준 글자 + 색. '찾은 이상 없음(정상 판정 아님)'은 그 문구 그대로.
- **근거 요약**: 시안의 '요약' 자리. **결정론 근거 개수**(예상 에러 묶음별 개수)와 AI 비정상 가능성(있을 때, 'AI 추정치' 표시)만. 문장을 만들어 쓰지 않는다.
- **결과 칸 3개**: 정상 패턴 일치 · 기존 비정상 사례 · 근거 충분성(이상 수준은 판정 칸으로 올라감).
- **권장 대응**: 지금과 같은 규칙·글. 대응이 없으면 '등록된 대응 방법 없음'과 도장 '대응 없음'. 결과 영역에서 판정 바로 다음(요구사항 CR-01 유지).
- **예상 에러 메시지**: 앞 3줄만, '모두 보기'는 ③으로. 비정상으로 보이지 않으면 이 칸 자리에 "비정상으로 보이지 않아 고르지 않았습니다".
- 근거 표·AI 의견·참고 자료·메모는 ②에서 뺀다(③으로).
- 분석 중에도 끝난 로그는 고를 수 있다. [취소]는 단계 막대 오른쪽 진행 막대 옆.

### ③ 상세 확인 (근거)

```
 ┌ 목록(좁게) ┐ ┌ 결과 — P4_004.log · R-0001   [비정상 의심]  정상 패턴 일부 · 사례 없음 · 근거 충분 ┐
 │▶P4_004.log │ │ 권장 대응 [매뉴얼 근거]  ①→②→③→④ (가로 칩, 누르면 글 전체)   출처: 사례 C-0012     │
 │ P4_005.log │ │ ▾ 예상 에러 메시지 (전체)          ▾ 참고 자료 (로그에 나온 코드)                  │
 │ …          │ │ ▾ 근거 (5)  근거 키 · 계층 · 종류 · 내용   ※ 두 번 누르면 아래 원문으로 이동           │
 │            │ │ ▸ AI 분석 의견 — AI 추정치 · 사용자 검토 필요     비정상일 가능성 75%               │
 │            │ │ ▸ 로그 원문 (이벤트 표·세션 타임라인)                                            │
 │            │ │ 메모: 가장 비슷한 정상 로그 C-0005(점수 0.97)와 비교…                             │
 └────────────┘ │ [◀ 분석 결과로]   [정상 사례로 등록] [비정상 사례로 등록]          [보고서 저장]  │
                └────────────────────────────────────────────────────────────────────────┘
```

- 지금 분석 화면의 결과 부분을 **접는 구역**으로 다시 묶은 것. 예상 에러·근거는 펴진 채, AI 의견·로그 원문은 접힌 채 시작.
- **원본 행 이동**: 근거·예상 에러·참고 자료를 두 번 누르면 '로그 원문'을 펴고 그 행을 고른다(지금 `show_line` 그대로).
- 왼쪽 목록은 ②와 같은 것을 좁게(파일 + 도장). 여기서도 로그를 바꿀 수 있다.

## 5. 학습(로그 입력) — 3단계

### ① 로그 넣기
신규 분석 ①과 같은 끌어 놓기 칸 + 목록(체크 칸 없음). 열: 파일 · 줄 · 이벤트 · 구분(—/정상/비정상) · 상태(저장 전/입력 중/저장됨).
[다음: 구분·메모 ▶]

### ② 구분과 메모
```
 ┌ 로그 (여러 개 고르기) ──┐ ┌ 선택한 로그 설명 ─────────────────────────────────────┐
 │☐ n1.log  —   저장 전   │ │ P4_016.log · 저장 전                                  │
 │☑ n2.log  정상 입력 중   │ │ 구분  (●) 정상  ( ) 비정상      ← 필수                   │
 │☐ a.log   비정상 저장됨  │ │ 메모(선택) [..................................]        │
 │  [모두 고르기]          │ │ (비정상일 때) 판단 가이드 [.........................]   │
 │                       │ │ (비정상일 때) 이 로그에서 에러로 보이는 줄 (자동)            │
 └───────────────────────┘ │ [저장 (바로 학습에 씀)]  [자세히 편집…]                    │
                           └──────────────────────────────────────────────────────┘
```
- 지금 '가져온 로그' 표 + '선택한 로그 설명' 카드를 그대로 옮김. 왼쪽 '올라온 로그'와 오른쪽 '가져온 로그'가 둘이던 것을 **하나로 합침**.
- 자동 저장 규칙 그대로(다른 줄로 옮기거나 단계를 바꾸면 구분을 고른 입력은 저장).

### ③ 저장과 AI 질문
- 위: **AI 질문**(지금 상자 그대로, 질문이 없으면 "새 질문 없음").
- 아래: **저장된 로그**(학습에 쓰는 중) 표, 두 번 누르면 ②로 불러와 고침.
- [◀ 구분·메모로] / [신규 분석으로 가기 ▶].

## 7. 화면 크기

- 기준 1366×768(작업 영역 약 1180×620): ② 오른쪽 카드는 **한 줄에 하나**(권장 대응 → 예상 에러 순), 1500px 이상에서 두 칸 나란히.
- 왼쪽 메뉴 160~180px, 분석 ② 왼쪽 목록 300px(경계선으로 조절, 최소 240px).
- 판정 칸·결과 칸·권장 대응 첫 3단계가 1366×768 첫 화면 안에 들어오는지 캡처로 잰다.

## 8. 테마에 더할 것 (theme.py 토큰·역할만)

| 역할 | 모양 |
|---|---|
| `nav`(왼쪽 메뉴 버튼) | 평평한 글자, 고른 항목은 강조색 옅은 바탕 + 강조색 글자, 묶음 제목은 보조 글 9.5pt |
| `step`(단계 버튼) `state=current/done/todo/locked` | 번호 원 + 이름. current = 강조색 채움·흰 글자, locked = 흐린 글자 |
| `verdict`(판정 칸) `tone=bad/warn/ok/neutral` | 큰 글자(16pt 굵게) + 옅은 상태색 바탕 + 테두리 |
| `step-number`(권장 대응 번호 원) | 강조색 테두리 원 + 숫자 |

- 아이콘: 외부 아이콘은 쓰지 않는다. 필요한 곳(판정 경고 등)은 Qt 기본 아이콘(`QStyle.StandardPixmap`)이나 `QPainter`로 그린 단순 도형만. 글자 기호(⚠·✓)를 아이콘 대신 쓰지 않는다(DESIGN.md 금지 규칙).
- 그림자·그라데이션 없음(지금 규칙 유지).

## 9. 결정 사항 (2026-11-22 사용자: "권장하는 대로 진행")

1. **분석할 로그를 체크로 고르기**: **넣음**(기본 모두 체크, 체크한 것만 분석). 작은 기능 추가.
2. **파일마다 상황 메모**: **넣지 않음**(지금처럼 분석 한 번에 하나). 파일마다 다르면 나눠서 분석.
3. **상세 확인**: **별도 단계(③)**.
4. **위 '관리' 메뉴**: **유지**(왼쪽 메뉴와 같은 동작).
5. **이름**: 왼쪽 메뉴 '학습'·'신규 분석', 단계 '로그 넣기 → 분석 결과 → 상세 확인' / '로그 넣기 → 구분·메모 → 저장·질문'.

## 10. 바뀌지 않는 것

판정·비교 규칙, AI 검증, 권장 대응 출처(승인된 매뉴얼만), 예상 에러 메시지 고르는 규칙, 저장 = 학습, 자동 저장, 보고서 내용, DB, 관리 대화상자.
