Local Log Analyzer 사용 가이드

처음 쓰는 분을 위한 안내입니다. 10분 따라 하기부터 해 보세요. 이 문서는 인터넷 없이 열립니다.

무엇을 하나용어처음 설정10분 따라 하기결과 읽기평소 사용외부 연결 차단문제 해결

1. 이 앱은 무엇을 하나

장비 로그를 이 PC 안에서만 분석합니다. 담당자가 “정상 로그”와 “비정상 로그 + 진단 가이드 + 대응 매뉴얼”을 사례로 등록하고 승인해 두면, 새 로그가 들어왔을 때 다음을 보여 줍니다.

  • 무엇을 하면 되는지 — 비슷한 과거 사례의 승인된 대응 매뉴얼 절차(화면 맨 위 “권장 대응”)
  • 무엇이 이상한지 — 오류 줄, 빠진 이벤트, 순서가 어긋난 곳(원본 행으로 바로 이동)
  • 원인 가설 — 로컬 AI가 근거를 붙여 정리한 가설(반드시 사람이 검토)
꼭 기억할 것
· 앱은 승인된 사례만 기준으로 씁니다. 사례가 없으면 비교할 수 없습니다.
· AI는 새 조치를 만들지 않습니다. 권장 대응은 사람이 승인한 매뉴얼에서만 나옵니다.
· “찾은 이상 없음”은 “정상”이라는 판정이 아닙니다.

2. 알아 둘 용어

용어뜻
사례로그 묶음과 설명. 정상 사례·비정상 사례 두 종류. 초안 → (정보 필요/검토 대기) → 승인 순서로 진행합니다.
승인담당자가 내용을 확인했다는 표시. 승인한 사례·항목만 분석에 쓰입니다. 고치려면 “수정 시작” → 다시 승인(이전 판은 보존).
운전 모드장비의 동작 상태 이름(예: 자동 운전). 정상 패턴은 모드별로 비교합니다. 관리자가 미리 등록합니다.
수집 세션“같은 시점에 함께 받은 로그”인지 “다른 날 다시 재현한 로그”인지의 구분. 다른 세션 로그는 시간을 섞어 보지 않습니다. 모르면 “모름”.
진단 가이드 / 대응 매뉴얼비정상 사례에 붙이는 문서(TXT/MD). 가이드는 필수(증상·기준·원인 등), 매뉴얼은 선택(대응 절차·주의사항·상위 지원 기준).
근거 키EV-0003 같은 번호. 결과와 AI 가설이 어느 로그 줄·사례를 근거로 했는지 가리킵니다.

3. 처음 설정 (관리자, 한 번만)

설치할 것은 없습니다. 받은 LocalLogAnalyzer 폴더를 통째로 원하는 곳(예: D:\LocalLogAnalyzer)에 복사하면 끝입니다. Python·Ollama·런타임을 따로 깔지 않습니다. Windows 10(1809 이상)·11 64비트에서 동작합니다.
폴더 안 파일쓰임
AI와 함께 시작.cmd평소에는 이것을 두 번 누릅니다. 폴더 안의 휴대용 AI 서버를 켜고 앱을 엽니다. 작업 표시줄에 “LLA AI 서버” 창이 작게 생깁니다(닫으면 AI가 꺼집니다).
LocalLogAnalyzer.exeAI 없이 앱만 엽니다. 결정론 분석과 승인된 매뉴얼의 권장 대응은 그대로 됩니다.
AI 서버 끄기.cmd다 쓴 뒤 휴대용 AI 서버를 끕니다. PC에 따로 설치된 Ollama는 건드리지 않습니다.
ollama 폴더휴대용 AI 서버와 모델. 지우거나 옮기지 마세요. 이 폴더가 없는 배포본은 AI 없이 동작합니다.

처음 실행할 때 “Windows의 PC 보호” 창이 뜨면 추가 정보 → 실행을 누릅니다(서명하지 않은 사내 도구라서 나오는 안내입니다). 앱 데이터는 %LOCALAPPDATA%\LocalLogAnalyzer에 생깁니다.

  1. AI와 함께 시작.cmd로 앱을 연 뒤 위쪽 파란 “처음 사용 안내” 띠를 따라 합니다.
  2. 관리 → 운전 모드 관리: 장비의 운전 모드를 등록합니다(이름·설명은 장비 사양 기준).
  3. 관리 → 설정: 사용할 로컬 AI 모델을 확인합니다. 휴대용 AI가 들어 있는 배포본은 그 모델이 미리 골라져 있습니다. 모델이 없어도 AI를 뺀 기능은 모두 동작합니다.
  4. 오른쪽 아래 상태 표시줄에서 Ollama: 연결됨을 확인합니다(“다시 확인” 버튼).

4. 10분 따라 하기 (연습용 파일 사용)

도움말 → 연습용 예제 폴더 열기로 연습 파일을 엽니다. 모두 가상 데이터입니다. 운전 모드가 없으면 먼저 “연습 모드”를 하나 등록하세요.

① 정상 사례 등록 — [정상 로그 학습] 탭

  1. 왼쪽 상자에 1_정상로그_A.log, 1_정상로그_B.log를 끌어 놓고 수집 세션은 “서로 다른 수집 세션”, 가져오기.
  2. 오른쪽: 제목 “정상 연습”, 운전 모드 선택 후 확인함 체크, 정상 판정 근거 “연습”.
  3. 패턴 후보 만들기 → 표에서 “필수”·“순서 제약”은 승인, 나머지는 거부.
  4. “AI 확인 질문”에 남은 질문이 있으면 답하거나 “건너뛰기”. → 승인. 상태가 “승인됨 · 개정본 1”이 됩니다.

② 비정상 사례 등록 — [비정상 로그 학습] 탭

  1. 2_비정상로그.log를 넣고 가져오기, 제목 “TEST-E001 연습”.
  2. 아래 상자에서 진단 가이드 첨부… → 2_진단가이드.md, 대응 매뉴얼 첨부… → 2_대응매뉴얼.txt.
  3. 가이드에서 증상·기준 채우기, 원인 확정 여부 “원인 추정”.
  4. 항목 표에서 모두 “승인” → 승인.

③ 새 로그 분석 — [신규 로그 분석] 탭

  1. 3_분석할로그.log를 넣고 가져오기, 운전 모드 선택 + 확인함.
  2. 분석 실행 → 오른쪽 맨 위에 “권장 대응 — 승인된 대응 매뉴얼 근거”와 주의 → 1·2·3 절차가 나옵니다.
  3. 근거 표의 줄을 두 번 누르면 왼쪽 로그의 해당 행으로 이동합니다. 보고서 저장으로 HTML 보고서를 남깁니다.

연습이 끝나면 관리 → 학습 사례 관리에서 연습 사례를 “보관”하세요(보관하면 분석에 쓰이지 않습니다).

5. 분석 결과 읽는 법

화면 부분읽는 법
권장 대응(맨 위)왼쪽 도장으로 먼저 구분합니다: 매뉴얼 근거 승인된 대응 매뉴얼의 절차, 가이드만 진단 가이드의 해결 방법만 있음, 대응 없음 비슷한 승인 사례가 아직 없음. 제목이 “승인된 대응 매뉴얼 근거”면 매뉴얼 절차, “진단 가이드의 해결 방법”이면 가이드만, “등록된 대응 방법 없음”이면 아직 비슷한 승인 사례가 없습니다. 각 줄 아래에 출처 사례와 문서가 있습니다.
결과 분류 칸 네 개권장 대응 아래의 칸입니다. 각 칸은 서로 독립된 판정이고, 글자 색은 초록(문제 없음)·주황(주의)·빨강(문제)·파랑(사례 있음)입니다. 색만 보지 말고 글자를 읽으세요.
정상 패턴 일치승인된 정상 패턴과 얼마나 맞는지. “판단 못 함”은 같은 모드의 정상 사례가 없다는 뜻.
이상 수준“승인된 규칙 위반”(필수 이벤트 누락·순서 위반) > “비정상 의심”(오류 줄·반복·지연) > “찾은 이상 없음”.
기존 비정상 사례 / 근거 충분성비슷한 승인 비정상 사례가 있는지, 판단할 근거가 충분한지. “판단 불가”면 결과를 믿지 마세요.
점수비슷한 사례를 고르는 순위 점수입니다. 확률이 아닙니다.
AI 원인 가설“관측 사실·원인 가설·대응 순서·추가 확인 절차·판단 불가”로 나뉩니다. “AI 제안 — 매뉴얼 근거 없음”이 붙은 절차는 참고만. AI 응답이 규칙을 어기면 저장하지 않고 “검증 실패”로 표시합니다.

6. 평소 사용

  • CS 현장: [신규 로그 분석]에서 로그를 넣고 권장 대응을 확인 → 보고서 저장.
  • 새 문제를 해결했으면: 분석 화면의 비정상 학습 사례로 등록 → 가이드·매뉴얼 첨부 → 승인. 다음부터 같은 문제에 권장 대응이 나옵니다.
  • 입력은 자동 저장됩니다(입력이 멈추면 잠시 뒤, 탭을 바꿀 때, 앱을 닫을 때).
  • 한 달에 한 번: 관리 → 백업 및 복원 → 지금 백업.
  • 로그 줄을 찾을 때: 이벤트 표의 필터, 여러 파일을 시간순으로 볼 때: “세션 타임라인” 탭.

7. 외부 연결 차단 확인 (관리자)

이 앱은 이 PC 안의 Ollama(127.0.0.1)에만 연결하고, 프록시 설정과 리디렉션을 따르지 않으며, 클라우드 모델은 거부합니다. 하지만 Ollama 프로그램 자체는 설정에 따라 인터넷에 접속할 수 있으므로 다음을 확인하세요.

휴대용 AI(앱 폴더의 ollama)를 쓰면 AI와 함께 시작.cmd가 서버를 이 PC 안 주소(127.0.0.1)에서만 받게, 클라우드 기능을 끈 채로, 앱 폴더 안의 모델만 쓰게 켭니다. 자동 업데이트하는 트레이 앱은 들어 있지 않습니다. 아래 2·3번은 PC에 Ollama를 따로 설치해 쓰는 경우에만 해당합니다.
  1. 명령 프롬프트에서 LocalLogAnalyzer.exe --check → “네트워크 안전 점검”에 [주의]가 없어야 합니다.
  2. Ollama 앱 설정에서 네트워크 공개(Expose) 끔, 비행기 모드(Airplane mode) 켬, 자동 업데이트 끔.
  3. 사용자 환경 변수 OLLAMA_NO_CLOUD=1 추가 후 Ollama 재시작(클라우드 기능 차단). OLLAMA_HOST는 비워 두거나 127.0.0.1.
  4. 더 엄격하게: IT 담당자가 Windows 방화벽에서 ollama.exe·ollama app.exe의 바깥쪽(아웃바운드) 연결을 차단. 트레이 앱 대신 ollama serve만 실행해도 업데이트 확인이 생기지 않습니다.
  5. 확인: 명령 프롬프트 netstat -ano | findstr 11434 결과가 127.0.0.1:11434 … LISTENING이면 이 PC 안에서만 받습니다.

8. 문제 해결

증상해결
승인 버튼을 눌러도 안 됨오른쪽 승인 검사에서 “막힘”으로 표시된 줄을 해결하세요(운전 모드 확인, 판정 근거, 가이드 첨부, 증상·기준, 원인 확정 여부, 필수 질문).
“맞는 파서 프로파일이 없어…”로그 형식을 몰라 한 줄씩 읽었습니다. 분석은 되지만 시각 비교가 안 됩니다. 관리자에게 파서 프로파일 추가를 요청하세요.
파일을 거부함TXT/LOG, 파일당 10MB 이하만 받습니다. 바이너리 로그는 텍스트로 바꿔 넣으세요.
Ollama: 연결 안 됨앱을 닫고 AI와 함께 시작.cmd로 다시 엽니다(설치된 Ollama를 쓰는 PC는 Ollama를 실행한 뒤 “다시 확인”). AI 없이도 나머지 기능은 동작합니다.
“AI 서버가 30초 안에 준비되지 않았습니다”처음 켤 때 백신 검사 때문에 늦을 수 있습니다. 앱은 열리니 잠시 뒤 아래쪽 “다시 확인”을 누르세요. 이미 이 PC에서 다른 Ollama가 돌고 있으면 그것을 씁니다. 그 Ollama에 같은 모델이 없으면 관리 → 설정에서 모델을 고르세요.
AI 답이 “검증 실패”로 표시됨AI가 근거 없는 내용을 써서 앱이 걸러 낸 것입니다. 결정론 결과와 권장 대응은 그대로 믿고 쓸 수 있습니다. 다시 실행하면 통과하는 경우가 많습니다.
권장 대응이 “등록된 대응 방법 없음”비슷한 승인 비정상 사례가 없거나 매뉴얼·해결 방법이 승인되지 않았습니다. 해결 후 사례로 등록하세요.
잘못 승인함사례 화면에서 “수정 시작” → 고쳐서 다시 승인, 또는 학습 사례 관리에서 “보관”.
