새 형식 시험 로그 50개 — Local Log Analyzer

모두 가상 데이터입니다. 실제 장비의 로그 형식, 오류 코드의 뜻, 동작 사양이 아닙니다.
(TEST-로 시작하는 이름과 TEST-E101 같은 코드는 뜻이 없는 시험용 문자열입니다.)

■ 구성
- 개발 중 테스트에서 쓰지 않은 줄 형식 10가지 × (정상 4개 + 비정상 1개) = 정상 40, 비정상 10
- 파일 이름(F01_jsonl_01.log …)으로는 정상/비정상을 알 수 없게 섞었습니다. 답은 정답표.txt에 있습니다.
- 정답표.txt: 파일마다 구분, 동작 메모 예, 판단 가이드 예(비정상만). 탭으로 나뉘어 있어 엑셀에 붙여 넣을 수 있습니다.
- 정상 로그는 모드 A(1사이클)·B(투입·정렬 + 2~3사이클)·C(5~12사이클)·C 긴 동작(25~40사이클)이 섞여 있습니다.
  정상 40개 중 20개에는 경고 줄(TEST-WAIT)이 한 번 이상 있지만, 기다린 뒤 이어서 정상으로 끝납니다.

■ 형식 10가지
  F01 JSON Lines        {"ts": "2026-11-11T13:14:22.103+09:00", "level": "info", "module": "TEST-CTRL", "msg": "TEST-START …"}
  F02 CSV               2026-11-11 12:44:11.976,INFO,TEST-CTRL,"TEST-START mode=B, lot=…, step=1"   (머리 줄 있음)
  F03 BSD syslog        <14>Nov  5 15:08:16 TEST-HOST01 TEST-CTRL[7110]: TEST-START …   (연도 없음, 초 단위)
  F04 슬래시 날짜       2026/11/10 15:32:06.080 [I] TEST-CTRL - TEST-START …
  F05 한국어 오전/오후  2026.11.05 오후 12:18:24.597 [정보] TEST-CTRL > 시작: TEST-START …   (CP949, CRLF)
  F06 logfmt            time=2026-11-11T06:52:28.357Z level=info comp=TEST-CTRL msg="TEST-START" mode=A …   (UTC)
  F07 유닉스 시간       1794108168264|INF|TEST-CTRL|TEST-START …   (밀리초, 세로줄 구분)
  F08 구역 머리 날짜    ==== 날짜 2026-11-12 ==== 아래에 [18:25:21.591] I TEST-CTRL    TEST-START …   (F08_sections_02는 자정을 넘김)
  F09 탭 구분 내보내기  Information<탭>11/14/2026 12:31:15 PM<탭>TEST-CTRL<탭>TEST-START …   (UTF-8 BOM, CRLF, 여러 줄 메시지)
  F10 ISO + 꺾쇠 레벨   2026-11-05T11:50:06.011026+09:00 <info> TEST-CTRL: TEST-START …   (들여 쓴 여러 줄 블록)

■ 비정상 10개는 종류가 모두 다릅니다
  오류 코드 반복 후 중단 / 기록이 중간에 끊김 / 45초 공백(시간 초과) / 값이 정상 범위 밖인데 레벨은 INFO /
  순서 뒤바뀜 / 재시도 폭증(결과는 OK) / 재시작 반복 / 구성요소 응답 없음 / 치명 오류 + 덤프 / INFO 줄 속 오류 코드

■ 쓰는 방법(예)
1) 지금 쓰는 데이터와 섞이지 않게 '관리 → 백업 및 복원'으로 먼저 백업해 두세요.
2) [로그 입력] 탭에 정상 40개를 올리고 '정상'으로 저장합니다(메모는 정답표 예를 써도 되고 비워도 됩니다).
3) 비정상 10개를 [신규 로그 분석] 탭에 하나씩 올려 앱이 무엇을 찾는지 봅니다.
   또는 비정상 몇 개는 [로그 입력]에 '비정상'으로 저장하고, 나머지로 분석해 봅니다.
4) 끝나면 '관리 → 학습 사례 관리'에서 시험 사례를 보관하세요.

■ 보강 뒤(CR-08, 2026-11-18)
- 10형식 모두 맞는 프로파일로 읽혀 시각·레벨·구성요소·오류 코드를 읽습니다
  (json_lines · csv_header · syslog_bsd · ymd_bracket_level · logfmt · epoch_pipe · time_only_date_header · tsv_header · generic_iso_level).
- 검출률(samples/evaluate_detection.py, 형식마다 정상 3개 학습 → 남은 정상 1개·비정상 1개 분석, 4번):
  비정상 40/40 = 100%, 정상 오탐 0/40 = 0%.
- 이 세트는 '줄 모양만 다르고 내용은 같은 제품 하나'라서, 여러 제품군에 대한 성능은 samples/제품군_세트로 따로 쟀습니다.

■ 보강 전 v0.3.0이 이 파일을 읽은 결과(2026-11-18, 임시 데이터 폴더에서 확인)
- 50개 모두 거부 없이 가져와집니다.
- F01~F09는 맞는 파서가 없어 '원문(raw)'으로 읽힙니다. 한 줄이 이벤트 하나가 되고, 시각·레벨·구성요소·오류 코드를 읽지 못합니다.
  그래서 ERROR 줄이나 TEST-E101 같은 코드가 있어도 '오류 코드/레벨' 근거가 나오지 않고, 45초 공백도 계산하지 못합니다.
- F10은 4개가 generic_iso_plain으로 읽혀 시각과 오류 코드(code=…)는 읽지만 <info> 레벨은 못 읽습니다.
  앞 50줄에 여러 줄 블록이 많은 1개(F10_isoangle_01)는 블록 줄이 형식 판정 점수를 깎아 원문으로 읽힙니다.
- JSON Lines(F01)는 따옴표 안 값을 모두 같은 자리표시로 바꾸기 때문에 모든 줄이 한 종류 이벤트가 됩니다.
  그래서 비정상 F01_jsonl_05가 정상 로그와 '비슷함 1.00'으로 나옵니다.
- 원문으로 읽힌 형식은 줄 앞의 시각 글자(오전/오후, AM/PM, T0/T1 등)가 이벤트 종류에 섞여서,
  정상 줄(TEST-START 등)도 '정상 사례에서 본 적 없는 이벤트'로 잡히는 경우가 있습니다.
- 정상 40개 저장 → 비정상 10개 AI 없이 분석: '이상 의심'이 나온 것은 F10 하나(TEST-E720)뿐입니다.
  나머지 9개는 '처음 보는 이벤트'(참고)만 0~8개 나오고 이상 근거는 없습니다. AI를 켜면 원문을 읽고 판단하므로 결과가 다를 수 있습니다.
