무작위 제품군 회차 평가 — Local Log Analyzer (CR-08 DT-12)

모두 가상 데이터입니다. 이벤트·구성요소 이름은 뜻 없는 TEST-음절 조합, 코드는 TEST-E###입니다.
실제 장비의 로그 형식·오류 코드의 뜻·동작 사양이 아닙니다.

■ 왜
직접 짠 세트(새형식_시험_50, 제품군_세트)는 결국 그 세트를 보며 규칙을 다듬었기 때문에, 처음 보는 로그에서도
통하는지 알 수 없었습니다. 그래서 씨앗만 바꾸면 처음 보는 제품군이 나오는 생성기를 만들고,
개선할 때마다 한 번도 안 본 새 회차 세트로 '고치기 전에' 먼저 재는 방식으로 반복했습니다.

■ 무작위로 정하는 것(제품군마다)
- 동작 구조: 시작부(시작·초기화·자체 점검·준비) + 본체 블록 2~3개 + 마무리부(정지·요약)
  본체 블록: 반복(동작 → 확인/기록/이동/적재 …) · 단계(진입 → 측정 → 나감, 3~6단계) ·
  동시 작업(접수 → 처리 시작 → (중간 처리) → 처리 완료가 작업자 2~4명에게 섞여 진행) ·
  주기 측정(채널 3~5개를 1초 안팎마다, 몇 주기마다 보고) · 분기(두 경로 중 하나)
- 어휘: 이벤트·구성요소·값 이름(뜻 없는 음절), 값 종류(측정값·정수·늘 같은 상태값·바뀌는 상태값·카운터·작업 번호)
- 로그 양식: 시각 13가지 × 레벨 9가지 × 칸 배치 6가지, 또는 JSON·logfmt·CSV(키 이름도 무작위)
- 고장(비정상 10개): 오류 후 중단·오류 한 번·기록 끊김·재시작 반복·공백·경고 폭주·단계 빠짐·순서 바뀜·값 튐·
  값 오름·값 멈춤·작업 미완료·작업 단계 겹침·작업 순서·작업자 빠짐·채널 끊김·상태값 바뀜·반복 단계 빠짐 중에서

■ 만들기·재기
  uv run python samples/make_random_family_samples.py --seed R5 --families 6 --out <폴더>
  uv run python samples/evaluate_detection.py <폴더>/R5_F1      (제품군 하나, 정상 1/4을 남기고 학습 → 분석 4번)
  폴더마다 정답표.txt(구분·고장 종류·판단 가이드), 회차 폴더에 제품군설계_<씨앗>.txt(동작 순서·양식).

■ 회차별 결과(2026-11-19, AI 없이 결정론 분석만, 제품군 6개 × 비정상 10개 × 4번 = 240회)
  회차   고치기 전(처음 보는 세트)          그 회차로 고친 것
  1회차  38% (92/240), 오탐 1%            자동 형식 인식(처음 보는 시각·레벨·칸 배치·JSON 키), 'k: v' 값 읽기
  2회차  86.7% (208/240), 오탐 0%         상태값 바뀜·이벤트 이름 단위 비교·기준 20개, JSON 유닉스 밀리초, [구성요소] 표기
  3회차  97.5% (6개 중 4개, 2개는 버그로 멈춤)  레벨 칸 없는 배치 버그, 짝 횟수 어긋남·통째로 없음, 포함도로 비교 기준 고르기
  4회차  91.7% (220/240), 오탐 0%         탭으로 나뉜 배치의 레벨·구성요소
  5회차  98.75% (237/240), 오탐 0%        (고친 것 없음 — 처음 보는 세트 두 회차 연속 90% 넘어 마침)
  남은 약점: 작업자가 많아 한 명 몫이 적을 때의 '작업자 빠짐'(5회차 4번 중 1번만 잡음).
  회귀: 새형식_시험_50·제품군_세트 5개 모두 100%, 오탐 0%(마지막 코드로 다시 잼).

■ 주의
- 비정상 종류는 제가 만든 고장 목록에서 고릅니다. 이 목록 밖의 고장(예: 미묘한 성능 저하)은 재지 않았습니다.
- 가상 데이터에서 잰 값입니다. 실제 장비 로그에서는 실제 로그로 다시 확인해야 합니다.
